# design.md — Huzaifa Pathan, personal site

The source of truth for the site. Re-read before touching any section. If code and this file disagree, the code is wrong.

Goal: a long-term personal site about Huzaifa, with a premium, product-company look (Linear / Vercel / Apple). Projects, papers and roles are equal pieces of evidence; **no single project is ever the centrepiece**. Personality comes from real content, density and interaction, never from decoration. Plain HTML/CSS/JS generated by a zero-dependency Node build. Content lives in `content/*.json`; design lives in `templates/`, `styles.css` and `script.js`. Adding a project, paper or job is a data edit, never a redesign (see CONTENT.md).

---

## 2. Type

- **Geist** 400 / 500: everything.
- **Geist Mono** 400 / 500: labels, metadata, stacks, code, JSON, diagram nodes, key caps, logs.
- **Instrument Serif italic** 400: ONLY one emphasised word per heading, coloured `--accent`. Max one per section. (Exception: the "hp" monogram in the photo fallback.)
- h1: 64px desktop / 40px mobile, weight 500, letter-spacing -0.045em, line-height 1.03, `text-wrap: balance`. Max 3 lines on desktop, never a single dangling word.
- h2: 40px / 30px, weight 500, letter-spacing -0.035em.
- Card titles: 26px Geist 500.
- Body: 17px, line-height 1.6.
- Labels: 13px Geist Mono, lowercase.
- Stat numbers: Geist 500, 32px. Stat labels: 13px mono `--muted`.
- Two-tone headlines (first sentence `--ink`, second `--dim`): homepage Hero and Contact only.
- No heading runs over 3 lines on desktop.

## 3. The window (signature component)

A neutral editor-style window, like a code-editor tab. Not a macOS window: no red/yellow/green dots.

```
.window        12px radius, --win background, overflow hidden, the only shadow on the site
.window-bar    38px tall, --win-bar background, 1px --win-line bottom border, flex, space-between
.window-tab    left: 0 16px padding, --win background (merges into the body),
               2px --accent top border, 1px --win-line right border, mono 12.5px --ink
.window-meta   right: mono 12px --muted, 14px right padding
.window-body   content
```

Shadow:
- Dark: `0 30px 60px -20px rgba(0,0,0,.55), 0 0 0 1px rgba(0,0,0,.25)`
- Light: `0 30px 60px -24px rgba(15,42,34,.22), 0 0 0 1px rgba(15,42,34,.08)`

Variants:
- **Profile window** (homepage hero): tab `huzaifa.json`, meta `profile`. Syntax-coloured JSON in Geist Mono 15px (13px mobile): keys `--accent`, strings and numbers `--ink`, punctuation `--muted`. Values are computed from `content/` at build time.
- **Flow window** (case-study pages only): tab `request_flow.md` (or the project's `flowFile`), stacked nodes with a note column and a one-line log.
- **Code window**: `.window.is-code`, fixed dark palette. 13px mono, never a horizontal scrollbar: each line is a block and wrapped continuations hang one indent level deeper.
- **Image window**: tab = image filename, meta = project slug, full width, lazy-loaded.
- **Command palette**: tab `commands`, meta `esc to close`.

## 4. Shape and space

- Radius: 6px key caps. 8px buttons, nodes, toggle, copy button. 12px windows and the photo. 16px cards and case-study panels. Nothing else is rounded (the simulation dot and the ● glyph are circles).
- No shadows except `.window`.
- Content max-width 1160px. 24px gutter on mobile.
- **Large screens** (min-width queries only, nothing changes below 1600px): the root font size goes 16px → 17px at 1600px → 18px at 1920px → 20px at 2400px, and the content width goes 1160px → 1320px at 1600px → 1440px at 2200px. All sizes, spacing, radii and window dimensions in styles.css are rem (= px ÷ 16), so the whole design scales together and is pixel-identical at the 16px root. Hairlines, borders and outlines (≤ 3px), breakpoints, the hero grid mask and the content widths stay in px.
- Spacing values in this file are written in px at the 16px root; in CSS they are rem.
- Spacing scale: 8, 16, 24, 40, 64, 96, 128px (cards use 28px padding by request).
- Section padding: 96px desktop, 64px mobile. Heading-to-content gap: 40px max.
- No screen should be more than ~40% empty.

## 5. Components

### Project card (homepage Work grid)
- `--surface`, 1px `--line` border, 16px radius, 28px padding, min-height 230px. The whole card is one link to its case study.
- Top: mono status + year. `● building · 2026` with "● building" in `--accent`; any other status (`shipped · 2025`) in `--muted`.
- Title 26px Geist 500, one-liner `--ink-2`, then at the bottom the stack (mono `--muted`) and `case study ↗` (`--accent`). A building project without a summary shows `case study soon` and isn't a link.
- Two-column grid of **equal** cards. If the count is odd, the last card spans both columns so there is never a hole. No featured card, ever.
- Archived projects live in a collapsed `<details>` row: "earlier work (n)".

### Résumé chooser (header "Resume ↗")
- With two or more résumés in `site.json`, "Resume ↗" opens a small `.window` panel (tab `resume.pdf`, meta `pick one`) listing each résumé by its `for` label ("AI / ML roles", "Backend / SDE roles"), each opening its PDF in a new tab. With one résumé it is a plain link.
- Built on `<details>`/`<summary>`, so it works without JS. JS adds Esc to close (focus returns to "Resume ↗"), ↑/↓ between options, and closing on click-away or tabbing out.
- Contact lists every résumé as its own link; the command palette gets one "open <label>" command per résumé.

### Rows
Now, Writing, Experience and archived projects use hairline rows (1px `--line` between). Each list has its own column layout so sections don't look identical.

### Stats
Computed at build time, never typed: projects shipped (status `shipped`) in About; `"projects"` in the hero JSON counts every published, non-archived project; internships (experience entries with `type: "internship"`), building since (earliest project year). No grades or marks anywhere on the site.

### Case-study page
Breadcrumb `← all work` · hero (kicker, h1 title, one-liner, status · year · role, link buttons) with the flow window on the right if the project has a `flow` · Problem / Decision / Trade-off in three columns with vertical hairlines · code window · image windows · results row · previous / next project.

| About | 300px photo left; label, h2, paragraphs, outside-code line, computed stats right |

## 7. Hard bans

- No gradients, glows, blobs, glassmorphism, cursor effects, noise. The one allowed `linear-gradient` is inside a `mask-image` that fades the hero grid out; it never paints a colour.
- No purple, indigo, orange, teal or any second accent.
- No Inter. No emoji (the ↗ → ← ✓ ● glyphs are text and are fine).
- No pill tags, "Live/New" badges or pulsing dots (the static ● is fine).
- No coloured left-border cards, no featured/hero project, no fake app screenshots or skeleton UIs.
- No slogan-only headings. No tiny uppercase wide-tracked labels.
- No inline `style=""` attributes. No hard-coded colours in components (code blocks excepted).
- No backdrop blur. The palette scrim is flat `--bg` at reduced opacity.

## 8. Content rules

- Nothing personal is hard-coded in templates: it all comes from `content/*.json`.
- Never invent code: snippets are copied verbatim from the real repositories.
- Never invent numbers. `results` holds only real, verifiable numbers; stats are computed.
- Empty fields are not rendered: no "undefined", no empty boxes, no empty sections.
- `draft: true` entries are skipped by the build.
- Copy-paste templates live in `content/templates/`; their placeholders start with `TODO:`. The build refuses to publish any non-draft content that still contains `TODO` and lists each field to fix.
- All JSON text is HTML-escaped when inserted.
- No grade-point average, marks or percentages about the owner anywhere (pages, JSON, meta tags).
- Simulation statuses are illustrative and never show measured-looking latencies.

## 9. Motion

One easing curve everywhere: `cubic-bezier(0.2, 0.8, 0.2, 1)`. Durations 150–500ms. Nothing bounces, spins, wobbles, pulses or glows.

**Allowed animations, and only these:**
1. **Hero JSON typing**: the `huzaifa.json` lines type in once, starting after the window `load` event and an idle callback so typing never competes with the first render (40ms per character, 1.5s max total), then a blinking lime block cursor (`steps()`, 1s).
2. **Headline entrance**: hero h1 lines fade up 12px, 60ms stagger per line, once, 500ms each.
3. **Section reveals**: each section's heading and content fade up 16px once when they enter the viewport (one IntersectionObserver, threshold 0.15, 450ms). Work cards stagger by 60ms. Never re-animate.
4. **Card hover**: border → `--line-2`, ↗ moves 3px right, card lifts 2px (`translateY(-2px)`), 180ms.
5. **Link underline**: a 1px `--accent` line draws left to right on hover, 200ms. Implemented as a `transform: scaleX()` pseudo-element, so only `transform` animates.
6. **Theme switch**: 200ms colour cross-fade on the page background and text only, not on every element.
7. **Copy-email button**: label swaps to "copied ✓" with a 150ms fade.
8. **Command palette**: opens with opacity 0→1 and scale 0.98→1 in 160ms; closes in 120ms. The résumé chooser panel opens with the same 160ms animation.
9. **Case-study pages only**: the flow window loops (dot travels through the nodes) and pauses when off-screen or when the tab is hidden. One loop at a time, driven by `requestAnimationFrame`.
10. **Live clock**: updates once per minute.

**Banned**: parallax, scroll-jacking or smooth-scroll libraries, cursor followers or glows, magnetic buttons, particle or WebGL/canvas backgrounds, animated gradients or blobs, typewriter effects on headings, marquees or tickers, infinite floating or bobbing, number count-ups, hover tilt/3D, confetti, splash screens, and any animation library (GSAP, Framer Motion, AOS, Lottie, Three.js). CSS transitions/animations and a few lines of vanilla JS only.

**Performance budget:**
- Animate only `transform` and `opacity` (plus colour for hovers and the theme switch). Never width, height, top, left, margin, box-shadow, filter or blur.
- No permanent `will-change`.
- Exactly one IntersectionObserver for reveals, unobserving each element after it animates. Zero scroll or mousemove listeners.
- Total JavaScript per page under 15 KB unminified, no external scripts. Images: WebP/AVIF, explicit width/height (the build reads them), `loading="lazy"` below the fold.
- Fonts: only the weights used, latin subset, `font-display: swap`. The build downloads them once and serves them from `/assets/fonts/` with an inline `@font-face` and a preload. A metric-matched local fallback (`Geist Fallback` = Arial at `size-adjust` 101.9% / 104.8%, `Geist Mono Fallback` = Courier New) keeps text from rewrapping when the web fonts arrive. If the download fails, the build falls back to a non-blocking Google Fonts link.
- `prefers-reduced-motion: reduce`: every animation and transition off except colour changes; final states shown instantly.
- Works with JavaScript disabled: reveal styles apply only after JS adds the `js` class to `<html>`.
- Targets: Lighthouse Performance ≥ 95 and Accessibility ≥ 95 on mobile, CLS < 0.05, no frame over 16ms at 4× CPU slowdown.

## 10. Behaviour

- Theme: inline `<head>` script reads localStorage (try/catch), falls back to `prefers-color-scheme`, sets `data-theme` and the `js` class before first paint. Toggle saves the choice. `theme-color` meta for both themes.
- Command palette: Ctrl/⌘+K or `/` opens it. Go to work, go to about, go to experience, copy email, toggle theme, open résumé. Arrow keys + Enter, Esc closes. `role="dialog"`, `aria-modal="true"`, focus trapped, focus returns to where it was. On case-study pages, "go to" navigates to the homepage section.
- Live clocks show Asia/Kolkata time.
- Scrollbar: kept (it shows position and is draggable), but thin and themed: `scrollbar-color: var(--line-2) var(--bg)`. Never hidden.
- Visible `:focus-visible` outlines in `--accent`. "Skip to content" link.
- WCAG AA for all body text in both themes.
- No horizontal page scroll at 360px. Check 360, 390, 768, 1280, 1440.
- Per-page `<title>`, meta description and Open Graph tags.
